# Тесты

**Тесты пишет человек.** Ты можешь предложить реализацию под готовый тест, объяснить, почему тест падает, и указать на дыру в покрытии.

## Что чем проверяется

- **Unit** — чистые функции домена (FIFO, P&L, конвертация валют). Без БД, без моков Prisma.
- **Property-based** (fast-check) — инварианты: сумма остатков лотов равна позиции, сумма `cash_ledger` равна балансу. Ловит то, чего не придумаешь примерами.
- **Интеграционные** — на Testcontainers, с настоящими PostgreSQL, Kafka, Redis. Мокать БД бессмысленно: половина логики живёт в SQL.
- **Гоночные** — отдельная категория: N параллельных попыток, успешна ровно одна. Такой тест обязателен для каждой операции, меняющей деньги.
- **E2E** — один сценарий на весь проект: регистрация → импорт → верная сумма портфеля.

## Правила

- Никаких обращений к живым внешним API. Только записанные фикстуры и sandbox.
- Время в тестах передаётся аргументом, а не берётся из `new Date()` внутри кода — иначе тест недетерминирован.
- Деньги в фикстурах — строки. `expect(x).toBe(0.3)` на деньгах — ошибка по определению.
- Тест на гонку должен падать на наивной реализации. Если он зелёный до того, как написан правильный код, он ничего не проверяет — перепиши.
- Настоящие брокерские отчёты в фикстуры не кладутся: только обезличенные, с выдуманными суммами.

## Именование

`*.test.ts` — быстрые, без контейнеров. `*.int.test.ts` — интеграционные. Описание теста — про поведение и по-русски: «повторный импорт не задваивает сделки», а не «should work correctly».
