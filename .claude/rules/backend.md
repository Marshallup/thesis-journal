# Бэкенд

## NestJS 12

- ESM. Воркеры (`core`, `ingestor`, `notifier`) — `NestFactory.createApplicationContext`, HTTP только для health-пробы.
- Валидация входа — Zod через Standard Schema в декораторах. `class-validator` не подключать.
- Переменные окружения читаются один раз при старте и валидируются схемой: приложение должно падать сразу и с внятным сообщением, а не через час на `undefined`.
- `enableShutdownHooks()` обязателен: по `SIGTERM` сервис дорабатывает текущую задачу и только потом выходит.

## Prisma 7

- Импорт `PrismaClient` — из сгенерированного пути, не из `@prisma/client`.
- Клиент создаётся с драйвер-адаптером `PrismaPg`.
- Транзакции — `$transaction` с колбэком; всё, что меняет деньги, происходит внутри одной транзакции целиком.
- Сырой SQL (`$queryRaw`) — нормально и ожидаемо там, где ORM протекает: партиции, `FOR UPDATE`, агрегаты, планы запросов. Не изобретать обходные пути ради «чистого ORM».
- Запросы пользовательских данных идут через `prisma.withUser(userId, …)`, чтобы работал RLS.

## События и очереди

- **RabbitMQ — команды** (сделать что-то: синхронизировать, распарсить, перелить). Ретраи, DLQ, ack после работы.
- **Kafka — события** (что-то произошло: тик, сделка записана, позиция изменилась). Ключ сообщения задаётся всегда: без него порядок внутри тикера не гарантирован.
- Публикация события — только через outbox в той же транзакции, что и бизнес-изменение. Прямая отправка в брокер из сервиса запрещена.
- Консьюмер: обработка и запись `processed_messages` в одной транзакции, коммит офсета — после. Автокоммит выключен.
- Формулировка в коде и комментариях — «effectively-once», не «exactly-once».

## Внешние API

- Любой вызов — через общий rate limiter на Redis (token bucket, атомарный Lua) и circuit breaker. Локальный лимитер в памяти процесса при нескольких репликах умножает трафик на их число.
- Ответ провайдера сохраняется сырым в `raw_imports` до нормализации.
- Не все операции — сделки: дивиденды, купоны, комиссии и налоги идут в `cash_ledger`.

## Ошибки и логи

- Структурные логи (pino) с `correlation_id`, который пробрасывается через заголовки Kafka и RabbitMQ.
- Ключи, токены и содержимое заметок в логи не попадают никогда.
- Ошибка внешнего провайдера и ошибка своей логики — разные типы: первая ретраится, вторая нет.
