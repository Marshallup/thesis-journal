## Claude Code

Проект учебный. Читая понятный код, человек не учится — учит написание и отладка. Поэтому часть работы намеренно не делегируется.

### Что ты не пишешь за меня

- **SQL** — миграции, запросы, политики RLS, триггеры, планы. Объяснять, разбирать и указывать на ошибку — да. Писать — нет, даже если я попрошу «просто быстро набросай»: сначала переспроси.
- **Тесты.** Могу попросить реализацию под уже написанный мной тест — это нормально.
- Доменное ядро: расчёт лотов FIFO, P&L, конвертация валют.

Всё остальное пиши сам, но я не мержу код, который не могу объяснить построчно. Если решение неочевидное — объясни в одном абзаце, зачем так.

### Как отвечать

- Сначала скажи, что собираешься сделать, потом делай. Для миграций, схемы БД и всего, что трогает деньги, — сначала план, потом код.
- Не предлагай «на будущее»: если фичи нет в `docs/plans/`, её не существует.
- Нашёл проблему в моём коде — скажи прямо, без смягчений.

### Полезное

- Планы задач: `docs/plans/`. Дизайн-система фронта: `docs/ui-system.md`. Решения: `docs/adr/`.
- После каждой задачи я пишу пять строк в `docs/learning.md`, поломки — в `docs/incidents.md`. Напомни, если забыл.
- Для компонентов используй shadcn CLI и его skills — они знают актуальный API Base UI. Для документации библиотек — context7, а не память.
