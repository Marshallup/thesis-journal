# Thesis

**Дневник инвестиционных решений.** Записано до, а не после.

Брокерское приложение показывает, *что* ты купил. Thesis хранит, *почему*: тезис, горизонт, уверенность и условие «я был неправ» — записанные до сделки и защищённые от правок задним числом. Сделки подтягиваются из бирж и брокерских отчётов, привязываются к решениям, и через полгода видно, какие мотивы приносят деньги, а какие — нет.

> **Статус:** в разработке, недели 1–4 из 9 закрыты. Публичной регистрации пока нет.

## Что уже работает

- **Решения.** Тезис, срок на исполнение, срок удержания, уверенность, настроение и условие «я был неправ». Ядро решения неизменяемо — его защищает триггер в базе, а правка создаёт ревизию.
- **Сделки.** Ручной ввод и импорт XLSX-отчёта Сбера: лоты по FIFO, позиции, движения денег, идемпотентность по номеру операции. Продажа, под которую в периоде отчёта нет покупок, откладывается и ждёт своего отчёта, а не теряется.
- **Привязка сделок к решениям.** Автоматически — когда сделка попадает в срок решения; руками — на экране «сделки без тезиса»; задним числом — с пометкой, которая исключает запись из оценки качества решений.
- **Котировки MOEX.** Опрос всей доски раз в пять минут плюс пятилетняя история дневных закрытий: стоимость портфеля, нереализованный результат, график цены с отметками сделок и решений.
- **Итоги.** По бумаге, по счёту и по валюте; исход каждого решения считается на чтении, а не хранится.
- **Разделение сервисов.** `ingestor` опрашивает биржу и разбирает отчёты в своей схеме БД, `api` получает результат событиями: команда через RabbitMQ (с повторами и отстойником), событие через Kafka (через outbox и с дедупликацией у потребителя).

## Зачем он существует

Есть личная причина и профессиональная, и обе честные.

Личная: журналы решений работают — но только если запись сделана в момент выбора, а не после того, как исход стал известен. Поэтому решения здесь неизменяемы: правка создаёт ревизию, оригинал остаётся.

Профессиональная: это учебный проект под смену трека с фронтенда на бэкенд. Домен выбран не по вкусу, а по тому, какие задачи он заставляет решать: конкурентная запись, идемпотентность, очереди, таблицы на миллионы строк. Подробности — в [docs/design.md](docs/design.md).

## Структура

```
apps/
  api/        REST + OpenAPI, аутентификация, сделки, решения, портфель
  ingestor/   опрос биржи, разбор отчётов, публикация событий
  web/        React SPA
  core/       ← появится: сделки и лоты переедут из api
  notifier/   ← появится: алерты и доставка в Telegram
packages/
  contracts/  типы событий, Zod-схемы, денежные примитивы
  db/         схема Prisma и миграции
docs/         дизайн, планы, ADR, конспекты
```

Монорепозиторий, а не два: типы событий общие для бэкенда и фронта, изменение схемы события правится одним коммитом, `docker compose up` поднимает всё. Обоснование — [ADR-0001](docs/adr/0001-monorepo.md).

Границы сервисов проведены по владению данными: каждый ходит только в свою схему PostgreSQL, в чужие таблицы — через API или события.

## Быстрый старт

```bash
pnpm install
cp env.example .env              # заполнить секреты
cp apps/web/.env.example apps/web/.env   # адрес API для dev-прокси, можно не менять
docker compose up -d             # postgres, redis, rabbitmq, kafka
pnpm db:migrate                  # миграции
pnpm db:role                     # роли приложения и воркера, идемпотентно
pnpm dev                         # api :3000, web :5173, ingestor :3001
```

Порядок важен: пароли compose берёт из рабочей копии `env.example`, в самом `compose.yml` их нет.
Без `POSTGRES_PASSWORD`, `APP_DB_PASSWORD`, `INGESTOR_DB_PASSWORD` и `RABBITMQ_PASSWORD` стек не
поднимется и скажет об этом прямо. Процессы падают при старте так же внятно, если нет
`DATABASE_URL`, `APP_DATABASE_URL`, `INGESTOR_DATABASE_URL`, `KAFKA_BROKERS` или `RABBITMQ_URL`:
приложение должно падать сразу, а не через час на `undefined`. На сервере эти значения задаются
окружением, а не файлом из репозитория.

Проверить, что поднялось:

```bash
docker compose ps                # четыре контейнера healthy
curl -s localhost:3000/health    # api: состояние базы
curl -s localhost:3001/health    # ingestor: то же для воркера
```

Тесты:

```bash
pnpm test          # unit + property-based
pnpm test:int      # интеграционные, на Testcontainers — поднимают реальные БД
```

## Как ведётся разработка

Проект учебный, поэтому процесс — часть замысла, а не бюрократия.

**Ветвление — trunk-based.** `main` всегда зелёный и задеплоенный. Ветки короткие: одна задача из плана = ветка `task/NN-<slug>` = PR в `main` со squash-merge. Ветки `dev` нет: она решает проблему релизных циклов и параллельных версий, которой у соло-проекта не существует, а стоит лишних мерджей. Деплой — по тегу `v*`.

**`main` защищён правилом:** PR обязателен, зелёный CI обязателен. Для одного разработчика это выглядит формальностью ровно до первого раза, когда правило ловит сломанный тест.

**Задача — это единица работы.** Не больше 4 часов и ~300 строк диффа, заканчивается зелёными тестами и запускающимся приложением. Не влезает — значит, это две задачи.

**Цикл одной задачи:**

1. прочитать кусок дизайна и пересказать своими словами — если не получается, читать снова;
2. написать тест руками;
3. написать код;
4. **сломать специально** — устроить гонку, убить консьюмера, отправить дубль;
5. пять строк в [docs/learning.md](docs/learning.md) своими словами;
6. PR с описанием и вопросом «что бы спросили на собеседовании по этому коду» — вместе с ответом.

**Что не делегируется ИИ.** SQL — миграции, запросы, политики RLS, триггеры — и тесты пишутся руками. Всё остальное можно генерировать, но не мержить, пока не получается объяснить каждую строку. Правила лежат в [CLAUDE.md](CLAUDE.md) и действуют на любого ассистента в этом репозитории.

Правило живое, а не декоративное: отступления от него помечены прямо в плане — у шага стоит «написано ИИ по просьбе» и дата. Так видно, какие куски придётся перечитывать внимательнее.

Причина простая: чтение понятного кода даёт иллюзию беглости, а воспроизвести его потом без подсказок не выходит. Учит написание и отладка, поэтому самое ценное здесь пишется вручную осознанно.

## Оговорки

Сервис не является инвестиционной рекомендацией и не даёт советов по сделкам — он лишь хранит то, что вы записали сами, и считает по этому статистику.

Биржевые API-ключи принимаются только в режиме чтения; ключ с правом на торговлю или вывод средств будет отклонён.
