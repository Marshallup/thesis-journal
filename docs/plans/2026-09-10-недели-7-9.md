**Цель:** закрыть конкурентное ядро (то, ради чего домен и выбирался), довести систему до эксплуатируемого состояния и собрать витрину, которую не стыдно дать ссылкой на собеседовании.

- Каждая задача недели 7 обязана иметь гоночный тест: N параллельных попыток, успешна ровно одна.

## Задача 48. Деплой на VPS

Перенесена сюда из задачи 6 решением от 19.10.2026: сначала работающий MVP, потом
эксплуатация. До этой задачи сервис живёт только локально, и правило AGENTS.md про
задеплоенный `main` выполняется наполовину.

**Файлы:**
- Создать: `apps/api/Dockerfile`, `compose.prod.yml`, `Caddyfile`
- Изменить: `.github/workflows/ci.yml` (выкат по тегу `v*`)

**Интерфейсы:**
- Отдаёт наружу: `https://<домен>/health` возвращает `200 {status:'ok',db:'up'}`; пуш тега
  `v*` выкатывает новую версию.

- [ ] **Шаг 1: Образ**

`apps/api/Dockerfile` — многостадийная сборка: `pnpm install --frozen-lockfile`,
`pnpm db:generate`, `pnpm --filter @thesis/api build`, в финальный слой только `dist`,
`node_modules` для прода и сгенерированный клиент Prisma.

- [ ] **Шаг 2: Сервер**

```bash
# на VPS
mkdir -p /opt/thesis && cd /opt/thesis
# перенести compose.prod.yml, Caddyfile и docker/postgres/init-app-role.sh,
# заполнить переменные окружения вручную
docker compose -f compose.prod.yml up -d
```

`Caddyfile`:

```
thesisjournal.app {
    reverse_proxy api:3000
}
```

Caddy сам получит сертификат Let's Encrypt.

Что надо не забыть, потому что к этому моменту это уже написано и работает локально:
`NODE_ENV=production` (иначе в прод поедет `pino-pretty` вместо JSON), секреты JWT **другие**,
чем локальные, и `CORS` под настоящий домен фронта.

- [ ] **Шаг 3: Миграции на проде**

`prisma migrate deploy` — отдельным шагом до старта приложения, не из кода. Накатывает только
применённые миграции, ничего не генерирует и не сбрасывает.

Перед этим — роль приложения: на пустом томе её создаёт init-скрипт из `docker-entrypoint-initdb.d`,
но если том уже существовал, скрипт пропущен. Прогнать его явно (он идемпотентный):
`docker compose -f compose.prod.yml exec -T postgres sh /docker-entrypoint-initdb.d/init-app-role.sh`.
Без роли приложение упадёт на `password authentication failed for user "thesis_app"`.

- [ ] **Шаг 4: Проверить снаружи**

```bash
curl -s https://thesisjournal.app/health
```

Ожидание: `200` и `"status":"ok"` с `details.database.status = "up"` — форма ответа задаётся
`@nestjs/terminus`.

- [ ] **Шаг 5: Выкат по тегу**

Отдельная job в `ci.yml` на `push` тега `v*`: собрать образ, выложить, перезапустить на
сервере. Секреты — в GitHub Secrets, в репозитории их нет.

- [ ] **Шаг 6: Коммит и тег**
