# Дизайн-система Thesis

Решение зафиксировано: **Base UI как слой поведения, shadcn CLI как способ доставки кода, внешний вид — полностью свой.** Обоснование выбора и отвергнутые варианты — `adr/0002-ui-stack.md`.

## Как это устроено

Три слоя, и путать их нельзя:

| Слой | Чей | Что в нём |
|---|---|---|
| Поведение | чужой | Base UI `@base-ui/react`: фокус, клавиатура, ARIA, позиционирование попперов |
| Доставка | чужой | shadcn CLI v4: `add` кладёт готовый компонент в наш репозиторий, дальше это наш код |
| Внешний вид | **свой** | токены, типографика, плотность, `Money`, `Stat`, таблица-регистр |

Узнаваемый «сгенерированный» вид берётся не из библиотеки, а из дефолтной темы. Поэтому правило жёсткое: **компонент, установленный из реестра, приводится к нашим токенам в той же задаче**, а не «потом покрасим».

## Идея

Продукт — журнал решений, а не торговый терминал. Половина экранов про то, что человек думал, вторая — про то, что из этого вышло. Отсюда единственная метафора, которой подчинено всё остальное:

> **Записанное выглядит иначе, чем живое.**
> Тезис — человеческий текст, сериф, статика, «бумага». Данные — гротеск с табличными цифрами, живая цена мягко перещёлкивается.

Это прямое следствие главной фичи (решение неизменяемо и записано до сделки), а не декоративный приём.

## Токены

Tailwind 4, CSS-first конфигурация. Файл `apps/web/src/styles/theme.css` — единственный источник правды по цвету и типографике.

```css
@import "tailwindcss";

@theme {
  /* Цвет */
  --color-ink:        #16233A;  /* основной текст, «чернила» */
  --color-ink-muted:  #5C6B7F;  /* вторичный текст */
  --color-paper:      #EFF1F3;  /* фон приложения */
  --color-surface:    #F7F8F9;  /* поднятые поверхности: шторки, поповеры */
  --color-rule:       #D5DAE0;  /* линейки и разделители */
  --color-accent:     #2447D8;  /* единственный акцент: ссылки, фокус, активное */
  --color-gain:       #0F766E;  /* прибыль */
  --color-loss:       #8B2C55;  /* убыток */

  /* Типографика */
  --font-serif: "Source Serif 4", Georgia, serif;
  --font-sans:  "IBM Plex Sans", system-ui, sans-serif;

  --text-xs:   0.75rem;   /* 12px — подписи в таблицах */
  --text-sm:   0.8125rem; /* 13px — интерфейсный минимум */
  --text-base: 0.9375rem; /* 15px */
  --text-lg:   1.125rem;  /* 18px */
  --text-xl:   1.5rem;    /* 24px */
  --text-2xl:  2.125rem;  /* 34px — только стоимость портфеля */

  /* Радиусы: маленькие. Документ, а не SaaS-плитка */
  --radius-sm: 2px;   /* поля ввода, кнопки */
  --radius-md: 6px;   /* модалки и шторки — и только они */
}
```

Цвета прибыли и убытка **не светофорные** намеренно: зелёный с красным — дефолт всех терминалов и худшая пара для дальтоников. Знак и направление обязаны читаться без цвета — цвет вторая подсказка, не первая.

Тёмная тема — после недели 9. Поддерживать две палитры в одиночку на девятинедельном проекте дороже, чем кажется, а метафора бумаги живёт в светлой.

## Типографика

- **Сериф** (`Source Serif 4`) — только человеческий текст: тезис, заметка, разбор. Длина строки до 70 символов, межстрочный 1.6.
- **Гротеск** (`IBM Plex Sans`) — интерфейс, подписи, все числа. Межстрочный 1.45.
- Все числовые колонки — `font-variant-numeric: tabular-nums`, иначе цифры прыгают при обновлении цены.
- Заглавные для подписей не используем. Иерархия задаётся размером и цветом, не капсом.

## Плотность и структура

Основная форма экрана — **регистр**, а не набор карточек: строки, тонкие линейки `--color-rule`, числа выровнены по правому краю, высота строки 32px.

Экран решения делится вертикальной линейкой: слева тезис (сериф, «бумага»), справа исход (гротеск, цифры). Разделение до/после — визуальное, без подписей.

Тени не используем нигде, кроме всплывающих слоёв (поповер, шторка). Тень как украшение — запрещена.

## Движение

Ровно одно место двигается само: стоимость портфеля через `@number-flow/react`. Всё остальное реагирует только на действие пользователя и показывает, что изменилось. `prefers-reduced-motion` уважается.

## Что откуда берём

| Задача | Решение |
|---|---|
| Диалоги, меню, поповеры, табы, тултипы | Base UI через `shadcn add` |
| Таблица журнала | `@tanstack/react-table` + `@tanstack/react-virtual` |
| Командная палитра | `cmdk` |
| Мобильные шторки | `vaul` |
| Диапазоны дат | `react-day-picker` 10 |
| Живые числа | `@number-flow/react` |
| Цены и свечи | `lightweight-charts` (TradingView) |
| Поведенческие срезы | ECharts или собственные SVG-спарклайны |
| Иконки | `lucide-react` |

`Recharts` не используем: это визуальный дефолт сгенерированных дашбордов, и на десятках тысяч точек он не тянет.

## Свои компоненты

Их немного, и это осознанно:

- **`Money`** — единственный компонент, которого нет ни в одной библиотеке: табличные цифры, валюта, знак, окраска по знаку, всегда работает со строкой.
- **`Stat`** — крупное число с подписью (стоимость, P&L за период).
- **`Registry`** — таблица-регистр с линейками и правым выравниванием чисел.
- **`Field`** — поле формы с меткой, подсказкой и ошибкой.
- **`Sheet`** — боковая панель для формы решения.

Всё остальное — из реестра. Своих кнопок и инпутов с нуля не пишем.

## Установка компонентов

```bash
pnpm dlx shadcn@latest init          # Base UI по умолчанию с июля 2026
pnpm dlx shadcn@latest add dialog table field
pnpm dlx shadcn@latest add --dry-run --diff <component>   # посмотреть, что изменится
```

Пресеты shadcn (`--preset`) не используем: пресет приносит чужую тему, а тема у нас своя.

## Чего не делать

Список из наблюдаемых признаков сгенерированного интерфейса — при ревью проверять по нему:

- палитра `zinc`/`slate` как основа, Inter как шрифт;
- контент, нарезанный на одинаковые карточки с одинаковым радиусом и одинаковой мягкой тенью;
- ALL-CAPS-надзаголовок над каждым блоком;
- стрелка `→` в тексте кнопок и ссылок;
- метаданные через средние точки «А · Б · В»;
- моноширинный шрифт для подписей «чтобы выглядело технично» (табличные цифры решают эту задачу честно);
- градиент как украшение;
- анимация появления у каждой секции при скролле.

## Открытые вопросы

- **Storybook 10** — примерно день работы, превращает систему в витрину, которую можно показать на собеседовании. Предлагаю ставить на неделе 9 вместе с остальной витриной, не раньше.
- Тёмная тема — после 1.0.
- Мобильная вёрстка: сейчас цель — десктоп и планшет, телефон получает только чтение портфеля и алерты.
